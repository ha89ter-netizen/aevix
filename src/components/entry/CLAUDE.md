# Живая система на входном экране

Читается, когда работа идёт с файлами входного экрана. Правила перенесены из корневого
`CLAUDE.md`: они касаются только этой директории и не нужны остальным сессиям.

- **Сцена на входном экране — постоянная архитектура, а не заглушка.** Рамка, метки и подпись
  остаются и после этапа 2; живая система стоит внутри плоскости. Текст героя не знает геометрии
  карточек.
- **Движение живой системы идёт на CSS, а не на кадрах JavaScript.** У каждого узла свой период и
  своя фаза; React просыпается только на перекладку путей и на редкое происшествие. Переписать это
  на `requestAnimationFrame` — значит вернуть шестьдесят перерисовок в секунду ради движения,
  которое человек не должен замечать. Замер, который это охраняет: ноль долгих задач главного
  потока. Анимация ставится на паузу, а не снимается, — иначе при возвращении на вкладку узлы
  дёргаются с нулевого кадра.
- **Слои живой системы не смешивать.** Данные (`capabilities.ts`), веса ниш (`profiles.ts`),
  логика (`graph.ts`), ритм (`use-ecosystem-life.ts`) и отрисовка разделены, и логика намеренно не
  тянет за собой React — иначе её нельзя проверить обычным тестом. Будущий разбор бизнеса меняет
  только профиль на входе.
